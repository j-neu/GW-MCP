# MT3D-USGS (legacy) post-processing — Design

**Date:** 2026-10-03
**Status:** Draft — for owner review
**Scope:** v0.3.0 remaining scope, sub-project 4 of 5. Follows the multi-model
foundation, GWE (sub-project 2) and PRT (sub-project 3).

---

## Goal

Read a legacy **MT3D-USGS** solute-transport run's concentration output and
plot its plumes through MCP tools, by **adopting an existing on-disk
MODFLOW-2005 + MT3D-USGS model directory**. No MT3D-USGS model is built and no
MT3D-USGS executable is run by the MCP.

The v0.3.0 gate (owner decision 2026-09-25) requires MT3D-USGS post-processing
to be built **and** put through the closed-book rerun loop (≥2 consecutive
green, last set-and-forget) against the **GMS "MT3D-USGS Keating"** tutorial
(owner decision 2026-10-03).

---

## Architecture decision (owner decisions 2026-10-03)

**Read-only post-processing, via a dedicated legacy subsystem.**

- **Read-only.** The MCP ingests an existing run's concentration output; it
  does not author MT3D-USGS input and does not execute the legacy binary. A
  "build and run MT3D-USGS" and an "MF6 GWT instead" scope were both considered
  and rejected.
- **Adopt the model directory.** MT3D-USGS output is grid-shaped, so reading and
  plotting need the grid. MT3D-USGS belongs to a legacy MODFLOW-2005 flow model
  the MCP does not model, so the tool adopts the model directory and reads the
  grid from it. Explicit-grid-parameters and reuse-MF6-grid alternatives were
  considered and rejected.
- **Dedicated subsystem.** The codebase is MF6-typed end to end
  (`model_store` caches `flopy.mf6.MFSimulation`, `components.ComponentSpec`
  maps to `flopy.mf6` classes, `adopt_model` hard-requires `mfsim.nam`, output
  discovery reads MF6 OC records). The legacy type therefore lives in a new
  `utils/legacy_transport.py` module with its own in-memory cache, reusing only
  the existing workspace registry and `.gwmcp_meta.json`. `model_store`,
  `components`, `grid`, and `runner` are otherwise untouched. Generalizing
  `model_store` was considered and rejected (largest regression surface for no
  functional gain).

Consequences:

- No `components` entry is written; a legacy model is not an MF6 component and
  never appears in `sim.model_names`.
- `run_simulation`, grid tools, and every MF6 builder are unchanged and
  unaware of legacy models.
- Derived artifacts (`.npy`, PNG) are written into the model workspace; legacy
  input files are never written.

---

## Target model

**GMS "MT3D-USGS Keating"** (`keating.zip`, Aquaveo GMS tutorials; catalogued
in `research/discovery/sessions/2026-08-15-aquaveo-gms.md`): a MODFLOW-2005
flow model with an MT3D-USGS transport model. The closed-book validation adopts
its model directory, reads its concentration output, and plots the plume. Target
specifics (file names, package set, output precision) are discovered during the
validation session; they do not constrain the tool surface below.

**Fallback if the tutorial ships inputs only:** run the shipped legacy model
as-is, outside the MCP, to produce the `.UCN`, then validate the read-only
tools against it. The read-only gate needs a concentration output to read.

## Design

### `utils/legacy_transport.py` (new)

Name-keyed in-memory cache of adopted legacy transport models:

- `LegacyTransportModel` dataclass: `name: str`, `workspace: Path`,
  `flow_model: flopy.modflow.Modflow`, `transport_model: flopy.mt3d.Mt3dms`,
  `version: str = "mt3d-usgs"`.
- `_LEGACY_CACHE: dict[str, LegacyTransportModel]` plus `_LEGACY_MTIMES`
  (mirroring `model_store`'s mtime-based reload).
- `adopt_legacy_mt3d_usgs(name, workspace, flow_nam=None, transport_nam=None,
  allow_modify=False) -> LegacyTransportModel` — loads the MODFLOW-2005 flow
  model with `flopy.modflow.Modflow.load(..., version="mf2005")` and the
  transport model with `flopy.mt3d.Mt3dms.load(..., version="mt3d-usgs",
  modflowmodel=flow_model)`. When `flow_nam`/`transport_nam` are omitted, the
  `.nam` files are discovered in `workspace` and classified by their package
  sets (flow: `DIS`/`BAS6`/`LPF`/`OC`/…; transport: `BTN`/`ADV`/`DSP`/`SSM`/…);
  ambiguous discovery is an error.
- `get_legacy_model(name) -> LegacyTransportModel` — cache hit, else reload from
  `meta["legacy"]` (`flow_nam`, `transport_nam`, `workspace`).
- `is_legacy(name) -> bool`, `clear() -> None` (test hook).

Grid access is the flow model's `modelgrid` / `dis` (structured DIS only);
this module does not import `utils/grid.py` or any MF6 class.

### `utils/workspace.py` (reused, unchanged)

`create_workspace(name, workspace)` registers the name→directory mapping and
`resolve_workspace(name)` resolves it, exactly as for MF6 models. A legacy
model is registered under the same registry.

### `utils/model_store.py` (one guard)

`get_sim(name)` / `get_model(name, ...)` gain a guard: if `name` is a legacy
model (`legacy_transport.is_legacy(name)`), raise a clear error naming the
transport tools instead of an opaque `KeyError`. No other change; the legacy
objects are not stored here.

### `tools/builder.py`

One implementation plus its wrapper:

- `_impl_adopt_mt3d_usgs_model(name, workspace, flow_nam=None,
  transport_nam=None, allow_modify=False) -> dict` — registers the workspace,
  calls `adopt_legacy_mt3d_usgs`, derives `units`/`time_units` from the
  MODFLOW-2005 model (`Modflow.get_units()` / `dis.itmuni`), writes the meta
  block below, and returns a summary. Read-only by default
  (`adopted: true`, `allow_modify: false`); legacy input files are not written.
- `@mcp.tool() adopt_mt3d_usgs_model(...)` wrapper, `_err`-enveloped.

`.gwmcp_meta.json` written block:

```json
{
  "name": "<name>",
  "units": "<flow length unit>",
  "time_units": "<flow time unit>",
  "adopted": true,
  "allow_modify": false,
  "legacy": {
    "type": "mt3d-usgs",
    "flow_version": "mf2005",
    "flow_nam": "<file>.nam",
    "transport_nam": "<file>.nam",
    "transport_packages": ["BTN", "ADV", "DSP", "SSM", "..."],
    "ucn_file": "MT3D001.UCN"
  }
}
```

`ucn_file` is recorded when an output file is present at adopt time; it may be
`null` and resolved at read time.

### `tools/postprocess.py`

Two implementations plus their wrappers, following the `read_heads` /
`plot_temperature_map` pattern:

- `_impl_read_concentration(model, ucn_file=None, kstpkper=None, layer=0,
  include_values=False, max_cells=10000, row_slice=None, col_slice=None)
  -> dict` — resolves the legacy model; locates the `.UCN` (explicit
  `ucn_file` > `meta["legacy"]["ucn_file"]` > workspace glob `*.UCN`/`*.ucn`);
  opens `flopy.utils.UcnFile(path, precision="auto")`; selects the time step
  (`kstpkper` 0-based; default the last record) and layer (0-based; a single
  layer, or all layers when `layer=None`); validates the array shape against
  the grid `(nlay, nrow, ncol)`; writes a `.npy` into the workspace and returns
  `{model, type: "mt3d-usgs", output_file, kstpkper, totim, layer, shape,
  MIN, MAX, MEAN, n_times}`, mirroring `read_heads`. `include_values` is gated
  by `max_cells`.
- `_impl_plot_concentration_map(model, kstpkper=None, layer=0,
  output_file=None, title=None, cmap="jet", vmin=None, vmax=None) -> dict` —
  reads via `_impl_read_concentration`, draws a plan view with
  `flopy.plot.PlotMapView(model=flow_model, ax=ax, layer=layer)` +
  `pmv.plot_array(...)` + colour bar, and saves a PNG via
  `utils/plotting.save_figure`. Returns `{model, output_file, layer,
  kstpkper, MIN, MAX, shape, type: "mt3d-usgs"}`.

The `plot_concentration_map` wrapper is declared `@mcp.tool(structured_output=False)`
and returns `[Image(path=...), result]`, as the other plot tools do.

### Error handling

| Situation | Result |
|---|---|
| workspace missing, or no `.nam` found | `OUTPUT_FILE_MISSING`, naming the expected name file |
| ambiguous MF2005/MT3D nam discovery | `INVALID_INPUT`, asking for `flow_nam`/`transport_nam` |
| non-structured (DISU/other) flow grid | `INVALID_INPUT` (flopy `Mt3dms` is DIS-based) |
| name already registered as an MF6 model (or vice versa) | `INVALID_INPUT` |
| no `.UCN` and none supplied | `OUTPUT_FILE_MISSING`, suggesting `ucn_file` |
| `UcnFile` precision `"unknown"` | `INVALID_INPUT` |
| `layer` outside `[0, nlay)` | `INVALID_INPUT` |
| `kstpkper` absent from the file | `INVALID_INPUT`, listing available `(kstp, kper, totim)` |
| an MF6 tool handed a legacy model name | clear "legacy model; use the transport tools" error (model-store guard) |

Wrappers catch and return `_err(code, message, suggestion)` using the existing
codes (`MODEL_NOT_FOUND`, `OUTPUT_FILE_MISSING`, `INVALID_INPUT`).

### Backward compatibility

MF6 flow-only and component workflows are unchanged: no MF6 module is edited
except the single additive guard in `model_store`. The full suite stays green
unchanged, and flow-only behaviour is byte-identical.

## Testing

- **Spike (plan Task 1)** — prove the flopy round-trip on a tiny synthetic
  fixture: `Modflow.load(version="mf2005")` + `Mt3dms.load(version="mt3d-usgs")`
  + `UcnFile` + `PlotMapView` over the legacy grid. The spike fixes the exact
  nam-discovery convention.
- **Unit** — a fixture writes a minimal legacy model directory (MODFLOW-2005
  DIS/BAS nam + MT3D BTN/ADV/DSP nam) and a hand-crafted binary `.UCN`
  (`numpy`/`struct`, mirroring `tests/test_7e_b.py::_synthetic_hds`). Tests
  cover: adopt loads and registers; `read_concentration` shape/values and
  `kstpkper`/`layer` selection; every error path above;
  `plot_concentration_map` writes a non-empty PNG.
- **Integration** — the adopt → read → plot path end to end on the synthetic
  fixture (no MF6 or MT3D-USGS executable required).
- **Regression** — full suite green; `ruff` + `mypy` clean; MF6 behaviour
  unchanged.
- **Closed-book validation** (release gate, separate session) — GMS
  "MT3D-USGS Keating" adopted, read and plotted MCP-only, ≥2 consecutive green
  reruns, last set-and-forget. Fallback per Target model above.

## Explicitly out of scope

- Building or running MT3D-USGS models (input authoring, the legacy binary).
- MF6 GWT (solute transport) — a separate capability, not this sub-project.
- MT3D-USGS mass-balance (`.mas`) and observation (`.obs`) readers.
- Concentration time-series readers/plots.
- Formatted (ASCII) concentration output (binary `.UCN` only).
- DISU/DISV legacy grids.
- Calibration targets / sensitivity for transport.
- MODPATH (legacy) — sub-project 5.

---

## Success criteria

1. An existing MODFLOW-2005 + MT3D-USGS model directory can be adopted through
   the MCP, registering the workspace and reading the grid from the flow model.
2. `read_concentration` returns the concentration at a chosen time step and
   layer (or all layers) with summary statistics and a `.npy` artifact.
3. `plot_concentration_map` renders a plan-view plume PNG from that output.
4. Every error path in the table is returned as a clear tool error.
5. MF6 usage and the full suite are unchanged; `ruff` + `mypy` clean.
6. The GMS "MT3D-USGS Keating" model can be adopted, read and plotted
   closed-book (release gate).
