## MCP findings (→ v0.2.0 backlog, filed in tasks.md)

- **`import_obs_from_csv` is broken on any model that ships with a continuous
  OBS6 package** — every call fails `OBS_IMPORT_FAILED: 'list' object has no
  attribute 'lower'`, independent of CSV contents, columns, layer, read-only vs
  modifiable clone, or site count (857-record OBS6 here; reproduces the
  mf6_freyberg run-1 finding — now confirmed on two independent adopted
  benchmarks). Obs-related introspection of the shipped OBS package is broken
  generally: `export_model_spec` also crashes on an obs name (`'sv_193'`,
  `could not convert string to float`).
- **No alternative obs-registration route exists**: no tool removes an existing
  OBS package, and `setup_calibration` (obs_source="model") requires
  import-registered targets; `setup_pest_control` (explicit) requires
  pre-existing `.tpl`/`.ins`, which are only generated by the gated
  `setup_calibration`. Adopted obs-bearing models without shipped PEST
  interface files (like neversink) therefore cannot be calibrated at all until
  the import defect is fixed.
- Minor server defect noted: a probe `create_model` routed its workspace to a
  non-existent `%TEMP%\tmp*` path (`.gwmcp_meta.json` mismatch).
