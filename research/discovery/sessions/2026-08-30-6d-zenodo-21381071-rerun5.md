## MCP findings (→ v0.2.0 backlog, filed in tasks.md)

- **Client-side MCP connection drops recur after long tool calls**: after
  `import_obs_from_csv` (a ~2M-cell spatial join, >60 s) the client returned
  `-32001 Request timed out` and then "unavailable tool 'invalid'" until the
  server was reconnected. Same class as rerun-4's drop. The tool completed
  server-side; the client dropped the session tool list. Root cause is
  client-side (the 60 s timeout dropping the MCP connection), but long-running
  tools (spatial joins, runs) are the trigger — worth a note in tools.md that
  `import_obs_from_csv` on very large grids can exceed the 60 s client timeout
  and should be resumed after a reconnect.
- **`setup_pest_control`'s obs_source="model" auto-generated instruction file
  can target the wrong output CSV name** (`gwf0_head.obs.csv` vs the adopted
  model's actual OBS fileout `0205_MF6_SS_Unconfined_250.ob_gw_out_head.csv`);
  the `output_files` pestpp option did not remap it. The agent used
  obs_source="explicit" with a hand-written canonical pif instead.
- **`w` instruction token is invalid on comma-delimited CSV lines in pestpp**
  ("EOL encountered while executing whitespace instruction"); use `!dum!` to
  discard skipped columns on CSV lines. Amend the canonical-pif guidance in
  tools.md.
