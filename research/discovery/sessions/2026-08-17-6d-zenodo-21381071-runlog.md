## Step 6 — Calibration chain (CRITERION 6)

### Pseudo-observation approach (documented decision)

No observed head values are shipped with the dataset. Observed values were derived
from the model's OWN reference output: after the base `hk.dat` run, the OBS6
continuous output `0205_MF6_SS_Unconfined_250.ob_gw_out_head.csv` (transposed
CSV: header row = obs names, second row = simulated heads) was read and used as
the pseudo-observation set. This makes the calibration a parameter-recovery test:
the "truth" is exactly the base parameter field, so a converged inversion should
return the base values with phi → 0.

Scope decision: a stratified subset of 121 of the 9,026 observations (every 75th
well/NHD site, all verified to lie on active cells) was used, to keep the
instruction file, .pst, and forward-run overhead manageable for a validation run
and the 60 s client timeout. Pseudo-obs mapping in `obs_subset_meta.csv`
(`o0001`…`o0121` ↔ original `w_*/nhd_*` names, rows/cols, pseudo obsval).

### Calibration inputs (built as data preparation)

- `hk.dat.tpl` (24 MB) — PEST template of the full K array generated from the
  shipped parzon workbook: 20 wide fixed-width tokens (`@hk_020514@` style,
  13 chars, comma-separated per row), `ptf @` header. Verified round-trip:
  substituting base values reproduces `hk.dat` row-for-row.
- `head.ins` — pyemu pif instruction file; one line per pseudo-obs
  (`l1 !dum! !o0001!` …) reading `obs_subset.csv`.
- `run_pestpp_model.py` — forward-model wrapper (stdlib-only) that runs `mf6`
  then extracts the 121 values into `obs_subset.csv`.
- `setup_pest_control(model="0205", obs_data=<121 pseudo-obs, weight 1.0>,
  par_data=<19 K-zone params, log transform, bounds base/100..base×100>,
  template_files=["hk.dat.tpl"], instruction_files=["head.ins"],
  pestpp_options={"model_command_line": "…", "noptmax": 3,
  "output_files": ["obs_subset.csv"]})` → wrote `0205.pst`
  (121 obs / 19 adjustable pars). Two instruction-format reprompts were needed:
  the MCP validates obs tokens via pyemu's pif parser, which rejects the
  `[l1]…@o0001@` style and accepts `l1 !dum! !o0001!`.
- Fixed the generated `.pst` mapping `hk.tpl hk` → `hk.dat.tpl hk.dat` so the
  parameterized K array is written to the file the NPF actually reads.
