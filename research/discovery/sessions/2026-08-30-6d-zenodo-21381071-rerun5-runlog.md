## 3. K-array generation (missing hk.dat)

Per the MCP-only constraint, the K array was computed with ordinary Python
(pandas/numpy) and injected through MCP tools — no hand-written `hk.dat`,
no direct flopy call.

- `parzon_0205_tpl.xlsx` = 1600 × 1252 zone tokens (`#hk_020501#`, `#hk_020515 #`,
  etc., 19 zones). Base realization row (`real_name='base'`, `rlz_name=0`) from
  `hk_3rlz_0205_c1.csv` provides the 19 zone K values.
- K array computed (float64, 1600×1252; 18 unique values, range
  0.00202309–16.6552 m/d). 2,003,200 cells cannot be passed inline through
  `add_npf_package`'s `k` argument (~12 MB JSON payload), so the documented
  spatial parameterise path was used instead:
  1. `set_model_crs` (AEA proj4 from `usgs.model.reference`, xorigin
     1422205, yorigin 2005535, angrot 0)
  2. Built a 19-zone polygon shapefile from the parzon token map (data prep,
     geopandas) with attribute `hk` = base-realization K per zone
  3. `add_npf_package(k=0.1 background, icelltype=1, k33=0.1, k_units=m/d)`
     to repair the broken NPF
  4. `assign_k_from_zones(shapefile, k_field=hk, layer=0)` →
     `zone_count=19, cells_matched=2003200, cells_unmatched=0`,
     `k_range=[0.00202309, 16.6552]` ✓ (matches base realization)
- MCP wrote `gwf0.npf` (34 MB inline K array) and rewired the GWF nam
  (`NPF6 gwf0.npf npf`). Model runnable.

## 9. Calibration chain (MCP-only)

### 9.1 PEST template
`gwf0.npf.tpl` generated (see §8 Recovery). Token parse was verified with
pyemu (`parse_tpl_file` → 19 parameter names). First attempt failed because
the template header was `ptf ~` while tokens were `@…@`; pyemu's template
parser uses the delimiter declared on the header line. Fixed to `ptf @`.
Setup: `setup_pest_control(obs_source="model", par_data=<19 K-zone params>,
template_files=["gwf0.npf.tpl"], pestpp_options={model_command, noptmax=5})
→ .pst written with 9026 obs / 19 adj params.

**Issue**: the tool's auto-generated instruction file (obs_source="model")
was named `gwf0_head.obs.csv.ins` and read `gwf0_head.obs.csv`, but the model
writes `0205_MF6_SS_Unconfined_250.ob_gw_out_head.csv`. The `output_files`
pestpp option did not remap it. Switched to `obs_source="explicit"` with a
hand-written canonical pyemu **pif** instruction file
`0205_MF6_SS_Unconfined_250.ob_gw_out_head.csv.ins`
(`pif ~` / `l1` (skip header) / `l1 ~,~ !name! ~,~ …`) reading the model's
real obs CSV, and explicit `obs_data` for a representative subset
(every-100th site, 91 obs). Pif parsing verified against the model's actual
obs CSV with pyemu's InstructionFile (91 values, matching pseudo-obs).

**pestpp crash found & fixed**: first IES run failed with
"EOL encountered while executing whitespace instruction" — the `w` token
is invalid on comma-delimited lines in pestpp. Rebuilt the instruction file
using `!dum!` (read-and-discard) for skipped columns; parse re-verified
(91 values). This is the canonical pif guidance: use
`l1/w/!dum!/!name!` in order, and for CSV lines use `!dum!`/`!name!` (not `w`).

## 10. Decisions & deviations from the source model

1. **Restored shipped files** from the dataset zip before adopting
   (holdout dir was contaminated by prior runs).
2. **K injected via `assign_k_from_zones`** (spatial parameterise tool)
   instead of `add_npf_package` inline array, because the 2,003,200-cell K
   array (~12 MB) cannot be passed as an inline tool argument. K values are
   identical to the run-script token replacement (base realization).
3. **Background run/calibration** (`start_run`/`start_calibration` +
   `get_job_status`) used because the model takes ~2 min to solve — a
   foreground call would exceed the 60 s client timeout.
4. **Pseudo-observation approach**: observed heads derived from the model's
   own reference output at the shipped OBS6 sites (documented above).
5. `check_model`/`validate_model` findings are inherent shipped-model
   properties and were accepted without modification.
6. Calibration used a **91-observation subset** (every-100th site) in the
   .pst to keep the explicit `obs_data` payload manageable and the IES
   runtime tractable; the instruction file skips the remaining columns
   with `!dum!`.
7. **Instruction file**: canonical pyemu pif written by hand (data prep)
   because the MCP's obs_source="model" auto-generated instruction file
   targeted the wrong output CSV name (`gwf0_head.obs.csv` vs the model's
   actual `0205_MF6_SS_Unconfined_250.ob_gw_out_head.csv`).
8. `summarise_calibration` / `run_ies_uncertainty` not yet run — the IES
   job was still running when the session stopped at operator request.
