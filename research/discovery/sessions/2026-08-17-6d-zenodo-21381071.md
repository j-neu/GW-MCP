## MCP findings (→ v0.2.0 backlog, filed in tasks.md)

1. **Adopt-existing-model gap**: MCP tools operate on the in-memory stub from
   `create_model`, not the adopted on-disk files. `summarise_model` returns
   empty packages, `check_model` reports no tdis/solution, while `run_simulation`
   correctly executes the on-disk model. A real-model adoption path (load
   existing simulation from the workspace) is needed.
2. **PEST++ on Windows**: pestpp cannot launch `.bat` commands (normalises `/c`
   to `\c`, hangs) nor space-containing paths (`GetExitCodeProcess` error) —
   requires a space-free wrapper. Document in `setup_pest_control`; consider
   generating the wrapper.
3. **60 s MCP client timeout** on `run_simulation` / `run_pestpp_ies` — runs
   complete server-side; agent ran the long calibration directly to keep the
   server responsive. Confirms the pre-registered Tier 2 async/status tool.
4. **Instruction-file format**: MCP validates obs tokens with pyemu's pif
   parser; `[l1]…@o0001@` style rejected, `l1 !dum! !o0001!` accepted. Document
   the pif format in `setup_pest_control` description.
5. **`.pst` template mapping**: generated `hk.tpl hk` → had to be fixed to
   `hk.dat.tpl hk.dat` manually. Cosmetic — align template target naming.
6. **Wide parameter bounds stress the Newton solve** (base/100–base×100 → failed
   forward runs); tightened bounds fixed it. Consider documenting/recommending
   tighter defaults in `setup_pest_control`.
7. **openpyxl missing from venv** — required to read the shipped parzon
   workbook; installed ad hoc.
