## 5. Pseudo-observations (documented approach)

No observed head values are shipped. "Observed" values were derived from the model's own reference output: the base run's OBS CSV (9,026 simulated heads). A deterministic subset of **129 sites** (every 70th site in OBS order — 89 `w_` wells + `nhd_`/`nwi_` sample) was used; each site's value = the base-run simulated head at that cell, located by (x,y) centroid (global = local + xll/yll). This is a perfect-model test: calibration should recover the base K field and phi ≈ 0, which it does (base phi 8.9e-14).

## 6. Deviations from the source model

1. **K injection mechanism.** The 2,003,200-cell K array cannot be transmitted inline through the MCP client payload (`add_npf_package`'s `k` argument is number-or-inline-array; a ~20 MB nested list is not transmissible; the server rejects over-size inline payloads for similar large arrays). The K field was therefore injected through the MCP-native spatial path: `add_npf_package` with the background constant, then `assign_k_from_zones` from a zone-polygon shapefile derived from the shipped parzon template + base realization. Result identical to writing `hk.dat` from the shipped procedure (verified values/range). This is the documented workaround for the payload limit; the K values are exactly the shipped base realization.
2. **NPF external-file reference restored for calibration.** The adopted+modified model reads K inline (`gwf0.npf`). No MCP tool can set NPF K to an external `OPEN/CLOSE` reference, yet PEST calibration requires the model to read the templated `hk.dat`. One line of the model nam file was restored to the **shipped** reference (`npf6 0205_MF6_SS_Unconfined_250.npf`) so the pestpp forward runs use the dataset's own configuration (NPF → `hk.dat`). This is a restore-to-shipped-state, not a rebuild; the base/validated model (inline K) is untouched in-memory.
3. **Background zone `hk_100000` fixed at 0.1 m/d** (not an adjustable parameter); the 18 numbered zones are the adjustable K-zone parameters.
4. **129 of 9,026 observations used** for calibration (pseudo-obs subset), and the shipped 9,026-obs package was replaced by the registered 129-obs package (`gwf0.obs`).
5. OBS6 observation names are uppercase in the CSV (`W_…`) vs lowercase in the OBS file; handled case-insensitively in data prep.

## 7. Tool gaps / limitations found

- **`summarise_calibration` does not support pestpp-ies output.** It looks for `<case>.par` (a GLM artifact). IES writes `<case>.<iter>.par.csv`, `<case>.<iter>.obs.csv`, `<case>.rei`, `<case>.phi.actual.csv` — none satisfies the tool. No workaround was applied (creating a fake `.par` would be a PEST-file hand-edit and is out of scope). Results were instead read from the IES output files (phi.actual.csv, `0205_c1.4.par.csv`). Success criterion 6's summarise step is therefore **partially unmet by the tool**, with this exact reason.
- No MCP tool can switch NPF `k` from an inline array to an external `OPEN/CLOSE` file (deviation 2 above).
- `run_simulation` exceeds the 60 s client timeout for this 1.14M-cell model; use `start_run`/`start_calibration` + `get_job_status` (verified via `get_run_log` on timeout).
